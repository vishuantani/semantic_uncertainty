How a question becomes a semantic-entropy score, and exactly where a neural network runs along the way.

The pipeline turns one trivia question into a number that predicts whether the model got it wrong. It does this in seven ordered stages. Only three of them run a neural network: the generator produces answers, an entailment model decides which answers mean the same thing, and the generator is loaded a second time to score the likelihood of what it already said. The other four stages are string surgery, ROUGE, tensor algebra, and roc_auc_score.

Everything below traces the mechanism of the _improved stack in this fork, which reorders one stage and re-scopes two others relative to the 2023 ICLR implementation it is forked from. Those departures are marked in rust throughout.

05What comes out

Stage 07 labels a question correct when ROUGE-L against the gold answer exceeds 0.3, then scores every measure by AUROC against 1 − correct. Higher is a better hallucination detector.

06Where this fork departs from the paper's implementation

Four changes to the stage graph, all of them consequences of one bug: correctness was being scored before the text was cleaned.

  • Scoring moved out of generate into its own stage after clean

    Upstream scored correctness inside the generation loop, which runs before any cleaning. ROUGE therefore compared a roughly 171-word repetition loop against a one-to-three-word reference: rougeL_to_target came out near zero for every question, correct was 0 of 40, and every AUROC in the analysis was nan. Stage 03 now sits between clean and similarities and writes the same bare keys back into the same pickle, so analyze_results.py is untouched.

  • Beam-search outputs are cleaned too, token ids included

    Upstream cleaned only the five sampled generations. The two beam answers stayed raw — which is what stage 03 grades and what stage 05 computes likelihoods over. Both the text and the ids are now cleaned so they cannot drift apart, and the raw fields are kept so the raw-versus-cleaned delta stays reportable.

  • Likelihoods prefer the cleaned ids, with a fallback that prevents a silent nan

    Stage 05 strips the padding that cleaning itself added — but only on the cleaned path, leaving the raw path byte-identical to upstream. If cleaning emptied a sequence, every label would be masked and the model would return nan, which would survive three stages and finally surface as roc_auc_score raising “Input contains NaN”. That one sequence falls back to raw ids instead: a worse number, but a finite and traceable one.

  • A wider ban list, and a check that every marker is one token

    The paper's six-entry list only bans capitalised markers; opt-350m escapes through lowercase question:, never emits a period, and runs to max_length. The extended list adds the lowercase and plural forms. Separately, only a marker's first token id is used, so 'Answers:' — which tokenizes as ['An', 'swers', ':'] — would silently ban every answer starting “An…”. Markers are now validated to a single token before use, which is how three fragmenting entries were caught.

Smaller changes

DeBERTa-base-MNLI replaces the large checkpoint so the entailment stage runs locally; its pair comparisons are batched per question and wrapped in no_grad. Every stage logs an aggregate line to Weights & Biases — non-finite counts, empty-after-cleaning counts, the fraction of questions with more than one semantic set — so a break surfaces at the stage that caused it rather than three stages later.

07Running it

One command drives all seven stages. Each runs as its own subprocess, so one stage's weights are released before the next loads its own.

python code/parse_triviaqa.py --num_examples 200        # once
python code/run_pipeline.py --wandb_run_name opt350m-baseline

--dry_run                  print each stage's exact command, run nothing
--start_from likelihoods   resume after a failure
--only generate clean      run a subset
--model opt-1.3b           swap the generator across every stage at once

--wandb_run_name is the one lever that matters: it names the single W&B run all seven stages log into and names the output/{sequences,entailment,likelihoods,confidence}/<name>/ directories, so a run's artifacts stay together instead of scattering under a W&B-generated name. Every other flag falls through to the stage script's own default, which keeps those scripts the single source of truth.
